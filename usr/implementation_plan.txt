OpenGL Renderer Implementation Plan
Generated from usr/spec.txt and the current project implementation.

Baseline Snapshot
=================

This project is currently a fixed-scene OpenGL renderer centered on Intel Sponza.
It is not just a starter app anymore. The implementation already contains a
deferred-style rendering path, async scene loading, Sponza asset bootstrap, and
several rendering/debug features.

Build and Assets
----------------

- CMake project targeting C++17.
- Visual Studio preset: windows-debug.
- Dependencies are provided either from external/ or FetchContent:
  - GLFW 3.4.
  - GLM 1.0.3.
  - fastgltf v0.9.0.
  - GLAD generated by upstream CMake helper.
  - stb.
  - Dear ImGui v1.92.7.
- CMake downloads Intel Sponza Base Scene from Intel when
  assets/main_sponza/NewSponza_Main_glTF_003.gltf is missing.
- assets/main_sponza is intentionally ignored because it is too large for git.
- The executable receives OPENGL_RENDERER_DEFAULT_SPONZA_SCENE from CMake, so it
  loads the source-tree Sponza scene directly instead of copying the multi-GB
  scene into the build output.
- Post-build staging copies only small runtime assets:
  - assets/shaders.
  - assets/texture.png.

Application Flow
----------------

- src/main.cpp owns the main program flow.
- GLFW creates an OpenGL 4.5 core profile context.
- GLAD initializes OpenGL entry points.
- app_input connects the global Camera to GLFW input.
- ImGui is initialized through imgui_layer.
- Default scene path is the CMake-provided Sponza glTF path unless argv[1] is
  provided.
- Scene CPU loading is async:
  - SceneAsyncLoader starts std::async work.
  - model_loader dispatches supported formats.
  - gltf_scene_loader performs actual fastgltf parsing.
- A loading screen is rendered while the scene file is loading.
- After CPU loading completes, the render thread creates G-buffer resources and
  uploads scene GPU resources.
- GPU upload reports progress through SceneGPUProgressCallback and the loading
  screen stays visible during shader compilation, mesh buffer upload, and texture
  upload.
- The loaded scene is framed automatically from CPU vertex bounds.

Scene Loading
-------------

- include/model_loader.h exposes load_scene(const char*).
- src/model_loader.cpp is now only a format dispatcher.
- include/gltf_scene_loader.h and src/gltf_scene_loader.cpp own glTF/GLB support.
- Supported scene extensions:
  - .gltf / .GLTF.
  - .glb / .GLB.
- glTF loading uses fastgltf with:
  - LoadExternalBuffers.
  - GenerateMeshIndices.
  - OnlyRenderable category.
- Node transforms are baked into CPU vertex positions and normals during import.
- Mesh vertex data contains:
  - position.
  - tex_coord.
  - normal.
  - tangent.
  - bitangent.
- Mesh index data is generated if absent.
- Material loading currently extracts texture paths for:
  - base color/diffuse.
  - normal.
  - metallic.
  - roughness.
  - occlusion.
  - emissive.
  - alpha mask via base color texture for glTF Mask/Blend materials.
- Material scalar/factor data is not yet preserved.

GPU Scene Resources
-------------------

- include/scene_gpu_resources.h defines GPU mesh/material handles.
- include/scene_gpu_resources_runtime.h exposes:
  - init_scene_gpu_resources.
  - clear_scene_gpu_resources.
  - render_scene_gpu_resources.
  - render_scene_gpu_resources_shadow.
- init_scene_gpu_resources currently:
  - clears old resources.
  - creates scene and shadow shader programs.
  - creates white and flat-normal fallback textures.
  - uploads each mesh to VAO/VBO/EBO.
  - uploads diffuse, normal, and alpha mask textures.
  - reports progress through SceneGPUProgressCallback.
- The GPU material struct currently stores only:
  - texture_diffuse.
  - texture_normal.
  - texture_alpha_mask.
- Metallic, roughness, occlusion, and emissive texture paths exist in SceneRaw
  but are not uploaded or used yet.

Shader and Texture Utilities
----------------------------

- graphics_util has:
  - compile_shader.
  - compile_shader_from_file.
  - create_shader_program_from_files.
  - load_texture_2d.
- create_shader_program_from_files centralizes vertex/fragment program creation
  and link error reporting.
- load_texture_2d uses stb_image and uploads RGBA8 textures with mipmaps.
- Texture color space is not yet distinguished:
  - base color/emissive should eventually use sRGB.
  - normal/roughness/metallic/AO should stay linear.

Current Render Path
===================

Pass Order
----------

The main loop currently renders:

1. Shadow pass.
2. G-buffer geometry pass.
3. SSAO pass.
4. SSAO blur pass.
5. Deferred lighting pass to the default framebuffer.
6. Optional point light markers.
7. Optional debug previews.
8. ImGui overlay.

G-buffer
--------

GBufferResources owns the current frame resources:

- framebuffer.
- texture_albedo: RGBA8.
- texture_normal: RGB16F.
- texture_depth: DEPTH_COMPONENT24.
- shadow framebuffer and depth texture.
- SSAO framebuffer/texture.
- SSAO blur framebuffer/texture.
- SSAO noise texture.
- fullscreen quad VAO/VBO.
- point-light marker VAO/VBO.
- shader program handles and uniform locations.

Current G-buffer outputs from assets/shaders/scene.frag:

- GAlbedo: sampled base color.
- GNormal: tangent-space normal mapped result when tangent is valid.

Missing G-buffer data for PBR:

- metallic.
- roughness.
- material AO.
- emissive.
- alpha mode/cutoff.
- material/object id.
- velocity.

Lighting
--------

Current deferred_light.frag is Lambert/Blinn-style simple lighting, not PBR.

It uses:

- G-buffer albedo.
- G-buffer normal.
- depth reconstruction.
- one hard-coded directional light.
- five hard-coded point lights.
- SSAO result.
- directional shadow map with 3x3 PCF.

GBufferResources hard-codes:

- directional light direction/color.
- point light positions/colors/intensities/ranges.
- shadow map size and projection constants.
- SSAO kernel/noise constants.
- ambient and diffuse strength.

Shadows
-------

- One directional shadow map.
- Orthographic light projection.
- Alpha mask support in shadow_scene shader through alpha texture.
- 3x3 PCF in deferred lighting.
- No cascaded shadow maps.
- No point/spot shadows.
- No runtime shadow controls.

SSAO
----

- Full-resolution SSAO target.
- 16 fixed sample kernel.
- 4x4 fixed noise texture.
- Separate blur pass.
- SSAO is applied as ambient occlusion in deferred lighting.
- Radius, bias, kernel size, and intensity are shader/code constants.

Debug/UI
--------

- imgui_layer shows a small "Renderer" panel.
- Current controls:
  - debug G-buffer views toggle.
  - point light markers toggle.
- Keyboard toggles:
  - P toggles debug previews.
  - O toggles point light markers.
- Debug previews show:
  - albedo.
  - normal.
  - depth.
  - SSAO blur.
- Loading screen uses ImGui and shows path/error/progress state.

What Is Already Done
====================

Do not plan these as future work unless the goal is cleanup/refinement:

- CMake Sponza auto-download.
- Ignoring assets/main_sponza.
- Avoiding build-output copy of the multi-GB Sponza scene.
- Async CPU scene loading scaffold.
- Loading screen during CPU scene loading.
- Dedicated glTF scene loader module.
- model_loader format dispatch.
- Centralized shader program helper.
- GPU upload progress callback.
- Basic deferred pipeline.
- Directional shadow map.
- SSAO and blur.
- G-buffer debug preview overlay.
- Tangent-space normal mapping when tangents are available.

High-Value Current Gaps
=======================

The next work should be based on these actual gaps:

1. main.cpp is too large.
   - It owns window setup, loading loop, progress composition, render loop,
     scene framing, and shutdown.
   - This is the first cleanup target before larger renderer changes.

2. Scene statistics are missing.
   - The loader logs counts to stdout, but runtime/UI does not store or display
     mesh/material/vertex/index/triangle counts.

3. Material import is incomplete.
   - Texture paths exist for PBR-relevant slots, but material factors and alpha
     metadata are missing.
   - SceneGPUResources only uploads three texture slots.

4. Shading is not PBR.
   - Deferred lighting uses Lambert-style direct lighting.
   - G-buffer lacks material properties.

5. Output is not HDR.
   - Deferred lighting writes directly to the default framebuffer.
   - There is no scene color HDR target, tone mapping, or gamma-correct final
     pass.

6. IBL is not implemented.
   - Sponza includes an HDR texture, but the renderer does not load HDR
     environment maps, cubemaps, irradiance, prefilter, BRDF LUT, or skybox.

7. Render settings are hard-coded.
   - Lights, shadow settings, SSAO settings, and debug modes should become
     runtime settings and ImGui controls.

8. Resource ownership is still manual.
   - Raw GLuint handles are stored directly in large structs.
   - There is no RAII wrapper for shader programs, textures, framebuffers,
     buffers, or vertex arrays.

9. Renderer pass boundaries are implicit.
   - GBufferResources owns too much:
     - G-buffer.
     - shadow resources.
     - SSAO.
     - lighting pass.
     - light marker drawing.
     - debug preview drawing.

Implementation Roadmap
=======================

Phase 1: Stabilize and Split Current Runtime
--------------------------------------------

Goal: keep current visuals, but make the code easier to extend.

Tasks:

1. Split main.cpp into focused functions/modules.
   - create_window_and_context.
   - initialize_runtime.
   - load_scene_with_loading_screen.
   - upload_scene_with_loading_screen.
   - frame_scene_camera.
   - run_render_loop.
   - shutdown_runtime.

2. Add SceneStats.
   - mesh count.
   - material count.
   - vertex count.
   - index count.
   - triangle count.
   - texture slot counts if useful.

3. Show stats in ImGui.
   - FPS.
   - CPU frame time.
   - mesh/material/triangle counts.
   - current scene path.

4. Make loading progress less heuristic.
   - CPU glTF loading progress is currently time-estimated.
   - Keep the estimate if fastgltf does not expose granular progress, but label
     it as "Reading scene file..." and reserve exact progress for GPU upload.

Verification:

- cmake --preset windows-debug.
- cmake --build --preset windows-debug.
- Run default Sponza.
- Run with an invalid scene path and confirm loading screen failure behavior.

Phase 2: Make Material Data PBR-Ready
-------------------------------------

Goal: import and store all glTF material data needed before changing lighting.

Tasks:

1. Expand SceneRaw::Material.
   - base_color_factor.
   - metallic_factor.
   - roughness_factor.
   - emissive_factor.
   - alpha_mode enum: Opaque, Mask, Blend.
   - alpha_cutoff.
   - double_sided.
   - normal_scale.
   - occlusion_strength.
   - texture_base_color name replacing or aliasing texture_diffuse.
   - texture_metallic_roughness.
   - texture_occlusion.
   - texture_emissive.

2. Update gltf_scene_loader.cpp.
   - Convert fastgltf material factors into SceneRaw::Material.
   - Preserve alpha mode and cutoff explicitly.
   - Preserve double-sided state.
   - Keep texture path resolution centralized.

3. Update SceneGPUResources::Material.
   - base color texture.
   - normal texture.
   - metallic-roughness texture.
   - occlusion texture.
   - emissive texture.
   - alpha mask/base color texture.
   - scalar factors.

4. Update texture loading.
   - Add load_texture_2d options for sRGB vs linear internal format.
   - Use sRGB for base color and emissive.
   - Use linear RGBA/R formats for normal, metallic-roughness, occlusion, alpha.

Verification:

- Build.
- Confirm all current textures still load.
- Confirm fallback textures are used for missing slots.
- Confirm no duplicate deletion of fallback/shared texture handles.

Phase 3: Expand G-buffer for Deferred PBR
-----------------------------------------

Goal: make the deferred path carry enough data for metallic-roughness lighting.

Tasks:

1. Add material G-buffer attachment.
   - Roughness.
   - Metallic.
   - AO.
   - Optional material flags/debug channel.

2. Add emissive path.
   - Either add an emissive G-buffer target or pack emissive where acceptable.
   - Prefer a clear explicit target if portfolio clarity matters more than
     attachment count.

3. Update scene.vert/scene.frag.
   - Use imported material factors.
   - Sample base color, normal, metallic-roughness, occlusion, emissive.
   - Apply alpha cutoff from material data.
   - Keep Blend materials in a temporary masked/opaque path until forward
     transparency is implemented.

4. Extend debug_buffer.frag and draw_debug_views.
   - Albedo.
   - Normal.
   - Depth.
   - SSAO.
   - Metallic.
   - Roughness.
   - AO.
   - Emissive.

Verification:

- Debug views show sane values on Sponza.
- Normal maps still face the correct direction.
- Alpha cutout objects still render and cast shadows.

Phase 4: Replace Lambert Lighting With Direct PBR
-------------------------------------------------

Goal: implement direct metallic-roughness PBR while keeping current pass order.

Tasks:

1. Add BRDF helpers to deferred_light.frag.
   - GGX / Trowbridge-Reitz NDF.
   - Smith geometry term.
   - Schlick Fresnel.
   - Energy conservation.

2. Apply direct lighting.
   - Directional light.
   - Current five point lights.
   - Current directional shadow map.
   - SSAO as ambient/material AO multiplier.

3. Make light parameters runtime settings.
   - Move hard-coded light data out of GBufferResources constants.
   - Add RenderSettings or LightingSettings struct.
   - Add ImGui controls for key values.

Verification:

- Non-metal materials remain mostly diffuse.
- Metallic materials show correct specular-dominant response.
- Roughness has visible effect.
- Lighting remains stable with Sponza scale.

Phase 5: Add HDR Scene Color and Tone Mapping
---------------------------------------------

Goal: stop writing lit color directly to the default framebuffer.

Tasks:

1. Add HDR scene color framebuffer.
   - RGBA16F color target.
   - Recreate on resize.

2. Render deferred lighting into HDR target.

3. Add final fullscreen pass.
   - Exposure.
   - ACES tone mapping.
   - Gamma correction.

4. Add ImGui controls.
   - Exposure.
   - Tone mapper selection later if desired.
   - Final output/debug target selector.

Verification:

- No washed-out albedo.
- No double gamma.
- Default framebuffer receives only final LDR output.

Phase 6: Add IBL and Skybox
---------------------------

Goal: implement the main visual upgrade from the portfolio spec.

Tasks:

1. Add HDR texture loading.
   - Use stb_image float path.
   - Start with assets/main_sponza/textures/kloppenheim_05_4k.hdr.

2. Add environment resources.
   - Equirectangular HDR texture.
   - Environment cubemap.
   - Diffuse irradiance cubemap.
   - Prefiltered specular cubemap.
   - BRDF LUT.

3. Add precompute passes.
   - Equirectangular to cubemap.
   - Irradiance convolution.
   - Specular prefilter mip chain.
   - BRDF integration LUT.

4. Add skybox pass.
   - Render after opaque scene or during final composition.
   - Add exposure and environment rotation controls.

5. Integrate IBL into deferred PBR.
   - Diffuse irradiance.
   - Specular prefilter + BRDF LUT.

Verification:

- Add debug previews for cubemap/irradiance/prefilter/BRDF LUT.
- Check metal, rough stone, and matte plaster areas separately.

Phase 7: Bloom and Post-Process Polish
--------------------------------------

Goal: complete a basic HDR post chain.

Tasks:

1. Add bloom.
   - Bright pass.
   - Downsample mip chain.
   - Upsample/composite.

2. Add controls.
   - enabled.
   - threshold.
   - intensity.

3. Add debug views.
   - HDR scene color.
   - bloom threshold.
   - bloom mip.
   - final LDR.

Phase 8: Renderer Architecture Cleanup
--------------------------------------

Goal: reduce the size and responsibility of GBufferResources.

Tasks:

1. Add lightweight RAII wrappers.
   - ShaderProgram.
   - Texture2D.
   - Framebuffer.
   - Buffer.
   - VertexArray.

2. Split passes.
   - ShadowPass.
   - GBufferPass.
   - SSAOPass.
   - DeferredLightingPass.
   - PostProcessPass.
   - DebugPreviewPass.
   - LightMarkerPass.

3. Centralize settings.
   - RenderSettings.
   - LightingSettings.
   - ShadowSettings.
   - SSAOSettings.
   - PostProcessSettings.
   - DebugSettings.

4. Add shader hot reload after ShaderProgram exists.

Phase 9: Viewer Features
------------------------

Goal: turn the app from a fixed Sponza demo into a useful glTF renderer/viewer.

Tasks:

1. Scene controls.
   - reload scene.
   - enter scene path.
   - reset camera.
   - screenshot capture.

2. Material inspector.
   - material list.
   - texture slot previews.
   - editable base color/metallic/roughness/emissive.
   - live GPU update.

3. Render/debug controls.
   - debug view selector.
   - pass toggles.
   - shadow controls.
   - SSAO controls.
   - post-process controls.

Advanced Targets
================

Only start after direct PBR + HDR + IBL + core controls are working.

Recommended order:

1. Cascaded shadow maps.
2. Forward transparent pass for glTF Blend materials.
3. Frustum culling.
4. GPU timer queries and per-pass profiler.
5. Render graph/frame graph.
6. Clustered lighting.
7. GTAO or SSR.
8. TAA.

Risk Notes
==========

- Keep Sponza in the source asset directory. Do not copy it into out/build.
- Do not add runtime asset downloads. Current configure-time CMake download is
  the correct boundary.
- Be explicit about texture color space before PBR work.
- Do not solve alpha blending inside the deferred PBR pass. Add a forward
  transparent pass later.
- Avoid a full render graph until pass ownership is clearer.
- Keep commits small because renderer changes touch shaders, CPU material data,
  GPU material data, and framebuffer layout at the same time.

  - material AO.
